# HarborGrid · 港口集装箱堆场作业协同与闸口调度系统

React + Vite + TypeScript 前端，Node.js + Express + TypeScript 服务端。面向中型集装箱码头，把船期、箱务、堆场区块、闸口预约、设备作业和异常闭环放在同一套作业控制台中。

## 启动

```bash
npm install
npm run dev
```

前端默认 Vite 端口 5178，API 默认 `http://localhost:4107`。

## 业务能力

- 船舶航次、泊位窗口、计划/已完成翻箱和延误风险
- 箱号、尺寸、冷藏温度、危险品级别、海关状态、进出口/中转流向
- 堆场区块容量、堆存热度、冷藏插座、危险品隔离和设备可达性
- 闸口预约时隙、车道、OCR/称重/封志校验状态与同车冲突检测
- 岸桥、场桥、集卡、正面吊设备池和约束感知任务队列
- 自动堆位推荐、冷藏/危险品约束、海关查验阻塞、任务指派审计
- **堆场容量预测与预警**：事件驱动的时间序列投影（航次 ETA/ETD、箱务方向、预约窗口、计划任务、区块封闭），逐箱/逐航次批量事件可溯源，支持版本替换、缓解动作模拟与执行后重预测
- React 控制台支持船期驾驶舱、闸口操作、堆场热区、容量预测与设备任务操作

## 容量预测模块

预测不是把当前 `occupied` 乘系数，而是把每个来源展开为带溯源的贡献事件后逐时间桶累加：

- **具名箱事件**：闸口预约（dropoff/pickup）、作业任务（卸船/装船/改堆/交付/查验）、在途箱按 ETA 推断、已签到按即时进场
- **航次批量事件**：剩余卸船量与出口集港量按计划速率摊薄到时间桶；装船批量离场逐桶受实际存量钳制（装不上计入集港缺口）。无历史样本时按计划速率估计，并在贡献依据中显式声明
- **边界情况**：取消预约 / 海关未放行提箱 / 扣留箱集港被排除（保留可追溯的 excluded 事件）；预约与任务描述同一物理移动时按确定性去重；查验放行后直接提箱则不回原区块
- **区块临时封闭**：封闭期容量冻结、只出不进，进场事件顺延到解封桶形成积压尖峰（`/api/yard/closures` 支持登记/修改/解除）
- **预测版本**：每次重算生成新版本并替换旧版本（`supersedes` 链），同时只有一个 active 版本
- **缓解动作**：改堆、预约改期、取消预约、推动查验释放、航次批量分流、提前解封；控制台先“模拟重预测”（不落库）再“执行并出新版”，建议卡片直接展示执行后的峰值与临界是否解除
- **溯源**：点击曲线任意时间桶，可看到该桶占用由哪些箱（具名）或航次批量事件贡献，含确定/估计口径、来源单据 id、去重与被动作改写的标注

相关接口：`POST /api/forecast/run`、`POST /api/forecast/simulate`、`POST /api/forecast/execute`、`GET /api/forecast/versions|active|:id`、`/api/yard/closures`。

当前使用内存种子数据，领域服务通过 REST API 暴露，后续可接入 TOS、OCR、称重、RTG 遥测、预约配额和优化求解器。
